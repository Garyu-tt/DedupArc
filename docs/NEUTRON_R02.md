# Neutron R02 — Mathematical Bytecode Storage (research branch)

**Status:** experimental, CPU-first, lossless. Not a release. New `--neutron` mode writes DARC v4, while default/max/Extreme continue to write v2/v3 respectively.

## Purpose

R01 exploits identical and near-identical blocks. R02 adds an orthogonal representation: an entire chunk can be a short deterministic mathematical generator plus exact patches. No models, external dictionaries, neural weights, or GPU are required for decoding.

## Bytecode

The uncompressed length and SHA-256 are already stored in DARC CHNK:

| Opcode | Parameters | Generated byte at index i |
| --- | --- | --- |
| `A0` | one constant byte C | `C` |
| `A1` | `start`, `step` | `(start + (i mod 256) * step) mod 256` |
| `A2` | period length P (1–32), P bytes | `pattern[i % P]` |

After the opcode and parameters: unsigned LEB128 patch count, then sorted `(gap: uvarint, exact_value: byte)` pairs. The initial previous-patch-end is 0; after a patch at offset `i`, it becomes `i+1`. The encoder includes **every** deviation, and the reader rejects malformed or out-of-range patches and verifies the final SHA-256.

Fitting uses bounded 4096-byte samples; the actual encoder checks all bytes and pays for every correction. Uncompressible candidates are skipped. The writer compares the **encoded length** against raw/zlib with a 16-byte minimum margin. Existing R01 XOR delta matching can still win if it is even smaller. Formulas are not assumed to compress arbitrary data.

## Test data / reproducibility

```sh
go test ./...
go vet ./...
go build -o deduparc-core ./cmd/deduparc
python3 scripts/benchmark_extreme.py --binary ./deduparc-core --workdir /tmp/neutron-r02-bench
cat /tmp/neutron-r02-bench/results.json
```

The benchmark has four **synthetic** categories: versioned random binaries (R01 strength), independent random blocks (negative control), text files (traditional compressors' strength), and formula-generated blocks (R02 strength). It verifies the extracted trees via SHA-256 and compares to `tar.xz -9` and (if installed) `tar.zstd -19`. Note that tar codec timing excludes tar creation; comparisons must not be treated as a standardized benchmark.

A local standalone Go math-codec smoke test, before integration, yielded:

| 65536-byte synthetic block | Math payload | zlib level 9 | xz preset 9 |
| --- | ---: | ---: | ---: |
| constant | 3 B | 84 B | 140 B |
| modular affine | 4 B | 585 B | 384 B |
| 7-byte period | 10 B | 125 B | 148 B |
| affine with 100 byte mutations | 285 B | not measured | not measured |

These are **codec payloads**, excluding DARC headers, file metadata and manifest. They are not representative of general-purpose compression. Whole-archive gains must be measured separately.

## Verified full-archive benchmark (2026-11-19)

Linux CI, Go 1.23, one reproducible Python seed, all archive sizes include DARC/tar metadata. **All four recovered file trees: SHA-256 PASS.** The math category was deliberately constructed from formulas; performance on real-world data is not inferred.

| Corpus | Source bytes | Maximum v2 | Extreme v3 | Neutron v4 | tar.xz -9 | tar.zstd -19 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Versioned binaries | 41,943,040 | 41,885,307 | 4,253,367 | 4,253,365 | 4,206,724 | 4,206,614 |
| Random binaries | 4,194,304 | 4,196,169 | 4,196,170 | 4,196,171 | 4,198,408 | 4,194,939 |
| Text configs | 1,837,782 | 24,813 | 24,817 | 24,815 | 24,212 | 22,580 |
| Mathematical patterns | 8,388,608 | 18,906 | 18,907 | **1,543** | 2,204 | 1,780 |

On mathematical patterns: **5436.557×** compression from source to complete v4 archive; **12.25×** smaller than R01. Whole-archive 256 KiB affine regression: Maximum=1856 B; Neutron=514 B.

Note: Zstandard's reported time excludes creating tar, so performance/time rankings are not directly comparable. These are intentionally synthetic, not an overall benchmark.

## Safety and compatibility

- v1/v2/v3 reading stays supported, v2/v3 writing unchanged for their original modes.
- v4 is not readable by previously released binaries. No silent auto-upgrade.
- Each generated output is deterministic modulo 256; no floating-point imprecision.
- Only bounded 32 MiB math chunks, maximum 32-byte periods and capped fit samples.
- Strict varint/range checking and full SHA-256 validation of reconstructed chunks.
- For unstructured data, fallback to existing raw/zlib/delta codecs.
- No claims of violating entropy bounds or compressing random data losslessly.
