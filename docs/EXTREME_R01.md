# Extreme R01 — адаптивное сжатие похожих бинарных данных

**Статус:** экспериментальный, lossless, CLI-only. **Дата:** 2026-11-08.

## Идея

DedupArc уже использует BuzHash CDC, SHA-256 exact dedup и solid-паки
мелких файлов. Это отлично убирает полностью одинаковые блоки,
но даже 1 изменённый байт меняет SHA-256 всего блока — хранить его нужно заново.

Extreme R01 использует следующее устойчивое сочетание:

1. CDC и точная дедупликация работают без изменений.
2. Для несовпавшего блока по восьми распределённым 64-байтовым
   отпечаткам ищутся похожие блоки того же размера.
3. Для кандидата считается точный XOR по всем байтам. Редкие изменения
   дают поток из нулей и немного ненулевых позиций.
4. Выбирается либо исходный raw/zlib, либо `SHA-256 базы + zlib(XOR)`,
   в зависимости от реального физического размера.
5. Базы сохраняются в обычном raw/zlib-формате, поэтому цепочек нет.
   При восстановлении обязательна проверка SHA-256 всего блока.

Размер кандидата ограничен 64 КиБ—1 МиБ, словарь — 64 МиБ.
Блоки solid-паков и другие неподходящие размеры используют обычный кодек.

## Результаты

Точные результаты и команды повторения — в [BENCHMARK.md](BENCHMARK.md).
На десяти похожих бинарных версиях (41 943 040 Б) Extreme получил
4 253 369 Б против 41 885 309 Б для Maximum v2.
Весь набор распакован и проверен по SHA-256.

XZ/Zstandard на этом же корпусе сжимают немного лучше; общая победа
над сторонними архиваторами не заявляется.

## Почему не используем каждый раз XOR или «семантические» дельты

Для несвязанных данных XOR не уменьшает энтропию и расходует место
на ссылку на базовый блок. Сохранение точной побитовой восстановимости —
жёсткое требование, в отличие от приближённого сжатия модели/изображения.
В текущем R01 поиск похожих блоков эвристический, но результат всегда
проверяемый и математически обратимый.

## Ограничения / планы

- `--extreme` доступен только через CLI, обычный интерфейс использует
  форматы и режимы без изменений.
- Формат v3 не декодируется устаревшими версиями DedupArc; v1/v2 читаются.
- Пока дельты применяются только к блокам одинаковой длины.
- Более универсальные варианты: смещённые совпадения (сдвиги/вставки),
  декомпозиция по типам файлов, обучение словаря без потерь,
  дополнительный сильный backend codec с отдельными лицензиями.
- Не пытаться объяснять низкую энтропию «информационной чёрной дырой»:
  размер архива ограничен информационной структурой исходных данных.
